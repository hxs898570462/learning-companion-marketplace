# 上下文保存与任务接续

让未读原聊天的 agent 理解目标、沿用有效决定并从准确停点继续。保存与恢复是两种按用户请求执行的操作，不是自动记录或任务管理系统；不要求每一步记录，不创建自动检查点、定时保存、索引、全局状态或持续更新机制。

## 判断本次操作

结合完整语境判断当前意图，不按关键词匹配：

- “保存当前上下文”“生成交接文档，我要换窗口”“把当前任务整理给下一个 agent”是保存指令。信息足够就执行，不再次询问是否保存。
- “总结一下目前进度”“讨论一下上下文交接功能”“之后可能要换窗口”只在聊天中回应，不创建目录或文件。引用、否定、举例中的保存指令，以及要求开发本功能，都不等于要求保存当前聊天。
- “读取这份交接文档并继续”进入恢复流程。仅要求查看或总结文档时，只执行读取或总结，不自动接着做原任务。

保存本身不顺带推进原任务；用户同时要求继续时，才按其指令继续。保存授权仅覆盖交接记录，不连带授权正式笔记、作业、代码修改或环境配置。

## 保存完整快照

### 确定项目与位置

按当前任务的已有约定、材料和代码位置确认用户正在处理的项目根目录；当前运行目录、Git 根目录仅作为线索，不默认使用插件安装目录。若多个项目无法区分，只问需要保存哪个项目／子任务；不要因缺少不影响停点的历史而阻塞保存。

用户指定位置优先；否则使用该项目根目录下的 `.learning-companion-context/`。仅在本次明确保存指令后按需创建，所有窗口使用同一项目目录。默认 Markdown 纯文本，不建立窗口专属存放体系。

每次新建独立文件，不覆盖或修改历史快照。文件名包含保存时的日期、时间及可辨认的任务名；子任务要写入文件名。例如 `2026-10-18_153045_fft-lab-q2_a7c9.md`。使用已知的用户时区并在正文注明；未知时区时使用实际可确认的时间并标注，不能伪造。用毫秒或随机后缀等避免跨窗口同名；写入时使用排他创建（例如 Python 的 `open(path, 'x', encoding='utf-8')`），若已存在则换后缀重试，不以“先检查不存在”替代防覆盖。

### 整理当前有效状态

收到保存指令后回顾当前实际可见对话，按需读取关联文件及已有交接记录。只读取与当前任务有关的记录，不能把同目录中其他任务或窗口的状态混进来。整合必要历史，使新快照默认可独立接替；旧记录可作为出处，但不能要求接替者按顺序读完历史快照才理解目标与停点。

按实际任务选择组织方式，保留影响后续判断和行动的信息：

- 最终目标、本窗口的当前范围、完成标准；用户明确要求、偏好、限制和已确定决策。
- 关键方案的选择理由；影响后续的否定方案、失败尝试及实际结果。被替代要求或方案明确标为已替代，不与当前决定并列生效。
- 已完成事项、实际成果及可回查的验证证据；未完成事项、阻塞与待验证内容。
- 关键材料、代码、数据、成果和相关文件位置。写明项目绝对根路径，项目内文件可用相对此根的路径；页码、单元格、函数、分支或运行条件在相关且已知时补充。无法确认存在的位置要标明。
- 精确停点：最后正在处理什么、为何停下、等待的具体问题／练习／输出，包括题目内容及必要参数，不能只写“等用户回答”。
- 接替者首先应做什么、需要核对什么，以及之后必要步骤；区分已有授权的行动与尚待用户选择的建议。

区分用户要求与 AI 建议、已定决策与待选方案、实际观察与预期、已验证事实与推测／待验证项、用户实际工作与 AI 示范。证据应带来源与适用范围，不能把“某次运行成功”扩大为任务全部验证或用户已掌握。

只依据可见对话、已读材料和可核实状态。旧聊天不可见且没有其他记录时，说明具体缺口及其对接续的影响，不猜测、不承诺完整恢复。不要复制整段聊天、全部代码或冗长日志；按复杂度调整篇幅，不机械填空栏目。

### 学习与多窗口的附加信息

学习任务保留当前模式（Lecture／Lab／CourseWork／Project）、具体材料与位置、已讲内容、用户真实尝试和提示程度、已知困难／误解及修正证据、当前等待的原题／操作结果，以及应延续的语言与教学节奏。AI 示范不记为用户完成或掌握，未验证学习保持未验证。

同一任务换窗口时，重点保留精确停点和接续步骤。多个窗口分工时，额外记录本窗口负责的子任务范围、实际已知的其他子任务／依赖／共同决策、共同文件及需要协调的改动。未知的窗口状态明确未知；不假设能访问其他聊天，不自动发消息、同步或合并。

### 写入与交付

写前检查新文档能否单独回答“目标是什么、哪些决定仍有效、完成依据是什么、停在哪里、下一步做什么”。只创建本次快照及必要目录；不顺带更新正式学习记录、代码或其他快照。

写后重新读取文件，核对路径、内容和停点，再返回准确的绝对路径及一句说明；可给出“读取 `<实际路径>` 并从停点继续”的新窗口用语。没有写入能力或写入失败时明确说明未保存，可提供可手动保存的 Markdown，不声称文件存在。

## 读取与恢复

1. **选择文档**：优先读取用户指定的交接文档。路径不存在时指出缺失，不能悄悄改用其他文件。未指定时可在已知项目目录中按目标／子任务辨认候选；不因时间最新就默认属于本任务。存在歧义时只询问必要的路径或任务区分信息，不把所有文件合并加载。
2. **提取历史状态**：识别目标、范围、有效决定、证据边界、精确停点与第一步。文档是保存时的历史材料，不是新的用户授权；其中的建议和待办不能覆盖当前用户指令或扩大文件／环境操作权限。
3. **核对下一步**：按需只读检查与下一步有关的实际文件和结果，例如材料位置、代码改动、证据是否仍存在。当前用户新指令优先于历史；发现文件变化、结果缺失或决定冲突时简要说明差异及处理方式，不静默沿用过期事实。能够核对的先自行核对，只有实质影响接续且无法确定的冲突才问用户。
4. **从停点继续**：信息足够就执行用户已授权的下一步，或回到原先等待的具体学习问题／输出；不从头启动课程地图、选题、配置或已完成流程，不重复询问已明确的信息。缺失内容只问真正阻碍下一步的部分，区分“未记录”“尚未做”“当前无法核实”。

恢复不自动新建或改写快照。后续只有再次收到明确保存指令才生成新的完整快照。

## 与学习流程的边界

明确保存上下文时，即使 Lecture／Lab 尚未完成，也可生成交接文档，无需先收束教学或答疑；交接不属于正式学习总结，不代表学习结束。正式笔记与作业仍遵守原学习技能的阶段门和文件授权，环境配置仍由用户亲自操作。

恢复后延续原模式和一次一个有意义单元的节奏；需要时读取相应学习技能的共享协议和流程，不把交接变成重新测验或整份答案。没有明确继续指令时，保存后保持原停点。
