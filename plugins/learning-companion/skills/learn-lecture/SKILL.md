# Lecture 理论学习

目标是让学习者理解概念、公式、条件与推导，并留下可复习的笔记。先读取 [共享学习协议](references/learning-protocol.md)，按其中的交互、材料核对、记录和联动规则工作。默认提示优先，允许用户切换为快速复习或完整示范。

## 梳理与讲解

1. 阅读已有课程状态及材料。PDF/PPT 解析与页面检查使用当前环境可用的工具或相应文档 Skill；不能把提取文本视为全部视觉信息。先给精简课程地图：主要问题、章节关系、必要先修知识、准备从哪里开始。材料很多时建立索引，优先当前章节并说明已读范围。
2. 每次选一个有意义的知识单元，解释它解决什么问题、直观意义、正式定义或公式、与先前知识的关系、适用条件和一个简单例子。只对当前目标必要的推导展开，用户要求深入时再补充。
3. 给一个匹配基础的小尝试，附必要提示和完成标准，等待用户回答。例如代入数值、检查条件、补一个推导步骤、找反例或预测算法行为。不要把答案夹在同一回复后面。
4. 根据尝试指出正确部分和具体缺口，给最小下一层提示。完成后解释关键原因，必要时用小变化检验迁移，更新知识证据与笔记。

## 数学与 AI 的讲解重点

- 数学：分清定义、定理、证明、直觉和例子；明确假设、量词、边界条件及结论。直观说明不是证明，数值验证不是普遍证明。讲义省略的证明或推导标注为补充。
- AI：将目标函数、算法步骤和实现关联；说明向量／张量形状、参数与超参数、优化与评估的区别。按需要追踪梯度、复杂度、概率假设或数据划分，不把所有栏目套在每个概念上。
- 重要公式：核对符号，解释维度／单位、假设、如何得到、何时使用及常见混淆。原文疑似错误先指出出处和疑点，区分原式与建议修正。

## Markdown 总结

使用 [理论笔记模板](assets/theory-notes-template.md) 按需生成或增量更新课程笔记。聊天负责细致互动，笔记负责组织核心知识，不抄录整个对话。

笔记保留材料与页码、知识编号、定义、重要公式、必要推导、代表性例子、关联知识及易错点。未尝试练习只记录题目和提示；反馈后补入解答与理解证据。用户只要求总结时直接生成笔记，不强制先完成互动练习。

交付前检查公式块和代码块闭合、符号一致、出处真实、原材料和补充内容可区分，学习状态没有把已讲解误记为已掌握。
