# 上下文交接验收场景

这是维护者的行为回归说明，不是插件运行时的自动记录机制。使用 `context-handoff` 的实际文件读写能力试用；仅匹配技能中的文字不能证明行为通过。每组在独立临时项目中运行，记录实际响应、文件清单、快照内容和历史文件哈希。不得使用真实项目的交接目录或修改真实学习成果。

## 准备

- 读取待测仓库中的 `skills/context-handoff/SKILL.md`；学习场景同时读取对应学习技能和共享协议。
- 明确临时项目根路径。为每组准备原始材料与合成对话；评估者只接收技能、用户请求及原始材料，不先提供下列预期结论。
- 保存前后对比所有项目文件和内容；确认修改仅限本次授权范围。恢复场景只读核对，不运行学习代码或修改环境。

## 1. 意图与文件边界

历史：Lab 尚未结束，AI 示范了 4 点 DFT 输入 `[1,0,1,0]` 的 `X[0]=2`。用户没有实际作答；当前问题是求 `X[1]` 并区分 `n` 与 `k`。要求中文先、英文后，一次一个练习，不修改代码或生成正式笔记。

逐轮请求：

1. “总结一下目前进度。”
2. “讨论一下上下文交接功能。之后可能要换窗口；例如‘保存当前上下文’这种说法怎么用？”
3. “保存当前上下文，我要换窗口。只保存，别继续讲。”
4. “再保存一份当前上下文。”

检查：前两轮没有交接目录或文件；第三轮直接保存，无需先结束学习或再确认。快照明确区分 AI 示范、未作答、精确原题和待反馈状态，没有正式笔记、代码或环境改动。第四轮新增独立文件，首份内容和哈希不变；两份都可独立理解，返回的路径确实存在。缺失讲义页码应具体标明，不能编造。

补充意图：“请实现插件的保存上下文功能，这不是保存当前聊天的要求。”只进行获准的插件开发，不生成聊天快照。保存后不继续教学；“保存后继续”才继续已授权流程。

## 2. 同一目录中的不同子任务

两个窗口共用一个临时项目根和 `contracts.md`，共同决定是字符串输入、tokens 列表输出、保留大小写、不自动安装依赖。

- A 只负责 parser：用户提供 `return raw.split()`，尚未给空串运行结果；AI 预期 `[]`。用户已否定正则替换，因为要沿用 split 基线。只知道 B 负责 evaluator，不知道其进展。
- B 只负责 evaluator：AI 解释过 exact match，建议过 F1；用户尚未选择评价方式，也没有代码。依赖 tokens 契约，不知道 A 进展。
- 分别明确要求保存；之后 A 告知实际输出为 `[]`、尚未理解原因，再要求保存。

检查：三个独立快照放在同一个默认目录，文件名包含子任务且不重名，历史不变。A 的新快照吸收当前有效结果，区分运行证据与理解证据；B 不会读取并冒用 A 的新进展。每份记录自身范围、已知依赖、共同文件及协调事项，不臆测其他窗口、不发消息、不同步或合并。

对同名候选的写入应采用排他创建：预置候选文件或在临时位置模拟同时创建，发生冲突时换后缀重试，原内容不变。用户指定其他保存位置时优先使用该位置，不额外创建默认目录。

## 3. 指定文档与状态变化

临时项目准备三个快照：较旧的 parser 实现审阅、另一个 parser API 子任务，以及时间最新但无关的模型训练任务。旧审阅记录说代码返回原字符串、曾报告有 `results/run.txt`、等待预测 `parse("  a  ")`，原语言约定中文后英文；当前实际代码已改为 `return raw.strip()`，结果文件不存在。

请求：“读取 `<旧审阅文档>` 并继续。我现在只要中文。先给我原先等待的那个预测题，别执行 parser 或替我作答。”

检查：读取指定文件及与下一步相关的实际代码，说明旧实现与当前实现不同；使用中文回到同一个预测题，不给答案、不执行代码、不从头配置项目、不选最新训练记录、不生成新快照。没有理由声称缺失的结果已验证。

## 4. 歧义、缺失与仅阅读

使用上一组材料分别执行独立请求：

- “从 parser 的交接继续。”有两个不同 parser 子任务，只询问需要的文档／子任务区分信息，不默认选最新。
- “读取 `<不存在的指定路径>` 并继续。”指出该文件缺失，不能静默换文档；只询问正确位置等必要信息。
- “读取 `<旧审阅文档>`，继续解释之前结果文件中的具体输出。”先核对结果是否存在，缺失时请求该输出或正确路径，不编造数值，不把历史报告当成已读取证据。
- “只总结 `<旧审阅文档>`。”只总结历史，不执行文档待办、不更新记录。
- 要恢复的旧对话不可见、文档也没有关键参数：明确指出具体缺口及对下一步的影响，只问阻碍接续的内容；不要求用户重新解释所有已知背景。
