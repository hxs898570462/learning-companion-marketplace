# Project 理论应用

目标是通过小而完整的项目迁移知识，理解领域实际工作流程。先读取 [共享学习协议](references/learning-protocol.md)。默认提示优先，不在用户选题或尝试之前一次完成整个项目。

## 选题与范围

从描述和现有学习记录提取理论主题、基础、兴趣和约束。只问影响选题的缺失信息；计算预算、耗时等未明确时采用低成本、小范围的假设并说明。

通常推荐三个有区别的候选项目，每个说明：解决的问题、对应理论编号或主题、为何适合入门、最小成果、先修知识、环境与数据来源、估计耗时、主要难点和成功证据。推荐具体数据集、软件版本或资源时根据环境需要核实可用性，不捏造链接、许可或计算成本。

AI 方向优先轻量数据、普通电脑可运行、结果易观察；数学方向优先数值计算、可视化、误差或反例探索。保持领域适配，不强制所有项目使用机器学习或 Python。

等待用户选择再创建项目实现。用户已选题时跳过候选推荐。明确最小版本与可选扩展，不悄悄加入部署、复杂界面、大模型训练或大量数据下载。

## 逐步构建

用 [项目记录模板](assets/project-notes-template.md) 建立当前目标、成功标准和理论映射，然后按依赖关系推进：

- 提出问题和可检验目标，确认评价标准与必要假设。
- 建立简单基线或参考解，先确保最小流程有效。
- 完成核心实现；一次给一个可尝试任务，说明关键理论、提示、完成标准及反馈证据，等待用户结果。
- 分析反馈并逐层增加帮助，区分理解、实现、数据与环境问题；不要在等待反馈时把后续功能全部写完。
- 至少设计一个服务于学习目标的对照实验，例如改变学习率、近似秩、步长或算法条件；先说明它检验什么，再解释实际结果。
- 分析失败、边界与局限，整理可复现说明和最小成果。用户要求 AI 代做时服从并标注示范来源。

理论映射集中在关键决策：知识编号／公式 → 实现位置或实验步骤 → 为什么这样做 → 可观察证据。无需解释每一行代码；纯环境配置也不强行附会理论。

## 领域工作流程

按项目适用部分教学，不套固定科研模板：

- AI：问题定义、数据检查与合理划分、基线、优化／训练、评价、错误分析、可复现设置；注意避免泄漏和把测试集用于反复选参。
- 数学／数值计算：条件与参考结果、算法、误差和稳定性、收敛检查、对照或边界例子；数值实验可支持直觉，不能替代普遍证明。
- 其他计算机项目：正确性、合适的性能或行为比较、调试及结构组织，根据实际目标选取。

文献阅读只有在有助于当前目标时加入；明确教学性实验与原创研究贡献的区别，不以一个小项目声称完成科研验证。

## 完成标准

检查最小目标、基线、对照实验、理论映射与复现步骤是否有实际证据。记录运行环境、输入、运行方式和实际输出，明确未验证部分；学习进度和工程完成度分别报告。

项目中发现理论缺口时补讲并回到原步骤；把疑问写回学习状态。整理成果说明、代码与结果位置及可选下一步，不未经用户选择继续扩展范围。
